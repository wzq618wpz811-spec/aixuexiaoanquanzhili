# 安全题库视觉卡片模板规格

版本0.3，研究设计稿。以下14类是模板，不是已完成14种在线自动出题能力。

来源范围、阅读工作量与坏题发现见[题库研究](question-bank-study.md)。原始题型和呈现模板分别记录。

## T01 单行为情境判断

原题来源形式：判断、两选一。启用条件：可进入内容设计。

必填槽位：场景范围、可见行为、正误命题、答案依据、关键局部。

画面结构：一张局部清楚的情境图 → 一句判断陈述 → 正确/错误按钮。

设计示例：实验用手套触碰公共设备：图中明确手套使用背景与接触对象。

质量检查：图片足以支持结论；禁止同时加入无关错误；保留原题否定与例外。

证据定位：CPU2025:434, TSU200:80。


## T02 同场景对照选择

原题来源形式：单选、判断改编。启用条件：可进入内容设计。

必填槽位：共同背景、唯一考查变量、2—4个选项、适用任务。

画面结构：等尺寸等画风的对照图 → 只有考查动作或部件改变。

设计示例：机械清屑工具或防护穿戴对比，保持人物与背景一致。

质量检查：不以表情、红绿或画质泄题；PPE与具体设备匹配；改编后的答案映射独立保存。

证据定位：QCU-M:18, QCU-M:68, QCU-M:89。


## T03 器材与标识识别

原题来源形式：单选、填空改编。启用条件：可进入内容设计。

必填槽位：规范图或实物照片、名称标签、适用场景、图形标准版本。

画面结构：器材/标识近景 → 文字名称按钮或图文配对。

设计示例：识别已核验的防护器材或警示标识；精确图形使用规范资源。

质量检查：安全标志不用自由生图重绘；同形不同功能须给铭牌；名称不可从颜色猜。

证据定位：JZCIT:4, JZCIT:42, NWU219:140。


## T04 场景热点核查

原题来源形式：多选、多个判断整合。启用条件：可进入内容设计。

必填槽位：场景、待查区域、可见事实、热点坐标、漏选误选规则。

画面结构：一张可放大场景图 → 直接点击区域 → 等价文字区域按钮。

设计示例：通道、插座周边、器材取用区域的可见遮挡核查。

质量检查：隐患必须可见或有明确状态标签；一处热点一条证据；不把未知状态当错误。

证据定位：TSU200:17, TSU200:57, TSU200:76, CPU2025:360。


## T05 任务检查清单

原题来源形式：多选、复合判断、简答要点。启用条件：可进入内容设计。

必填槽位：具体任务、独立检查项、并行关系、例外设备、依据。

画面结构：场景概览 → 任务与状态卡 → 勾选需完成项目。

设计示例：入室或离室核查，明确哪些设备需要持续运行。

质量检查：检查项目不强行排序；持续运行例外明确；不把一幅空房图当无人值守证据。

证据定位：CPU2025:425, CPU2025:456, QCU-M:86, TSU200:54。


## T06 设备状态与参数对照

原题来源形式：判断、单选、数值填空。启用条件：设备与数值依据核验后启用。

必填槽位：设备型号、读数及单位、额定条件、状态信息、数值依据版本。

画面结构：设备简图 → 清楚的铭牌/读数板 → 选状态或范围。

设计示例：用明确的额定信息与运行状态判断，图只负责定位部件。

质量检查：所有数值由程序排版；负荷、接地、无电状态不能靠外观；不泛化旧阈值。

证据定位：TSU200:2, TSU200:10, TSU200:19, QCU-M:78。


## T07 标签与记录找证据

原题来源形式：单选、多选、判断。启用条件：可进入内容设计。

必填槽位：标签/记录字段、有效性、主体与日期、需查证事实。

画面结构：容器或门牌图片 → 可读标签局部 → 点击缺失或冲突信息。

设计示例：检查模糊试剂标签或不完整责任记录。

质量检查：化学性质来自已给信息；不让模型补造授权/检测合格；日期与主体必须对应。

证据定位：CPU2025:405, CPU2025:439, CPU2025:463, TSU200:70。


## T08 分类与位置匹配

原题来源形式：单选、多选、判断、简答要点。启用条件：分类规则核验后启用。

必填槽位：对象标签、类别依据、容器/区域、相容性限制、例外。

画面结构：带文字标签的对象卡 → 目标区域图 → 点选匹配或分类。

设计示例：将已注明类别的废物或物品匹配到管理区域。

质量检查：不靠液体颜色判断成分；化学相容性必须核验；分类不是操作混合演示。

证据定位：CPU2025:454, CPU2025:457, NWU219:88, NWU219:97。


## T09 聊天与通知辨识

原题来源形式：情境单选、情境判断、多选。启用条件：可进入内容设计。

必填槽位：发送方身份声明、渠道、消息内容、请求动作、核实线索。

画面结构：仿聊天/邮件界面 → 关键内容与链接域名 → 选择回复或下一行动。

设计示例：退款、借款、账号异常通知等情境，核实信息比人物表情更重要。

质量检查：使用虚构身份与不可点击示例域名；头像不等于身份核实；聊天话术不直接抄长原题。

证据定位：CPU2025:207, CPU2025:248, CPU2025:538, CPU2025:585。


## T10 条件变化决策

原题来源形式：首要行动单选、条件判断。启用条件：可进入内容设计。

必填槽位：当前条件、可见/不可见信息、行动选项、条件改变点。

画面结构：一个场景加条件卡 → 选择当前行动 → 必要时展开一条条件变化。

设计示例：遇到设备异常或未经许可的任务，依据明确条件选择处理方式。

质量检查：不凭原单题编造完整事故程序；新增分支要另有依据；报警与撤离不可自动强排全序。

证据定位：CPU2025:403, CPU2025:447, QCU-M:7, QCU-M:12。


## T11 案例证据拼图

原题来源形式：长情境多选、案例简答。启用条件：可进入内容设计。

必填槽位：案例事实、事实来源、角色关系、关键证据、问题目标。

画面结构：场景/简短分镜 → 两至三张事实卡 → 勾选风险原因或防范要点。

设计示例：复杂校园情境拆成可读的事实，不把长题一口气塞到图片上。

质量检查：真实案例与题库虚构案例分别标注；不把多项正确内容改成单选；人物姓名前后不一致先修题。

证据定位：CPU2025:502, CPU2025:165, CPU2025:295。


## T12 路线与空间判断

原题来源形式：情境单选、多选。启用条件：空间依据核验后启用。

必填槽位：准确平面图、当前位置、出口/通道状态、方向条件、问题边界。

画面结构：简化可读的平面示意 → 点击路线或位置。

设计示例：提供明确路口或通道图后再问位置/路径，不靠模糊透视猜。

质量检查：普通图片不能证明真实距离；地图方向与场景一致；疏散路线必须现场核验。

证据定位：CPU2025:302, CPU2025:521, CPU2025:527, TSU200:76。


## T13 有依据的步骤拖排

原题来源形式：独立排序、顺序单选改编。启用条件：有原题且现行先后依据审核通过才启用。

必填槽位：完整原题、原始排列答案、现行流程依据、设备/人员范围、先后约束、并行与分支说明。

画面结构：3—5张步骤图卡 → 拖动手柄 → 键盘移动备选。

设计示例：当前只用中性步骤占位演示拖动；已找到的专业顺序原题保持待审。

质量检查：缺完整原题或现行依据不出正式题；清单和首要行动不是全序；改变交互须新版本/分开统计。

证据定位：LZU:p55:q1103, NWU219:sequence-filter, TJU2019:competition。


## T14 职责与规则关系图

原题来源形式：概念单选、制度判断、简答。启用条件：制度与职责已核验后启用。

必填槽位：现行制度片段、角色职责、前提与例外、适用学校、学习目标。

画面结构：角色/机构关系示意 → 授权或手续卡 → 选对应主体或缺失环节。

设计示例：将准入、权限、报告对象做成关系图；法规记忆题不能仅加吉祥物装饰。

质量检查：不能以服装年龄推断资格；图必须帮助理解关系；无视觉教学价值则退回设计，不发纯文字卡。

证据定位：TSU200:37, TSU200:41, TSU200:77, CPU2025:413。


## 通用生图约束

先固定 knowledge_point、scope、visible_evidence、hidden_facts、correctness_basis、target_difference。角色参考只控制身份；服装与PPE由任务控制。背景、角色、道具、标签、状态层独立。正误选项在人物、背景、光照、细节密度上保持一致。

图中不绘正确/错误标记，不用表情暗示答案。题干所需的文字与数字由代码排版。输出后检查额外隐患、遮挡、部件错误、标签、动作可判性。

## 失败回退

缺依据、题干条件不充分、视觉信息不足或模型无法保证专业细节：进入疑题/内容设计队列。不得默认发布，也不得自动退回纯文字题。

## 数据契约

机器可读版本：[config/card-templates.json](../../config/card-templates.json)。每题记录原题定位、知识类型、可观察证据、必需条件、模板版本、改编原因和检查结果。
